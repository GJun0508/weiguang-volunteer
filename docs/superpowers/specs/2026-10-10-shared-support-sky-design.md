# 共和小学支教行动 · 共享微光星空设计

**状态：** 对话设计已确认，等待用户审核本规格。
**日期：** 2026-10-10

## 目标

把旧版捐款演示中的星空互动移入共和小学支教行动网站，改成访客表达线上支持的共享星空。访客可以选择支持意向、点亮一颗星、观看星星飞入星空，并查看其他访客公开点亮的星星。该互动不接收或暗示真实金钱捐赠。

## 已确认的设计

- 用户确认星星对全站访客共享。
- 星星主要玩法保留：星空画布、点亮后飞入、星点呼吸效果、点击星星查看信息、其他访客的新星加入共享星空。
- 支持方向采用固定选项：**特色课程、家庭走访、物资准备**。它们表示访客关注的行动方向，不表示相关活动或物资已经完成。
- 访客可以为星星写一句 1–60 字的短留言；不收集自定义昵称。留言会随星星公开给全站访客。
- 点亮前明确提示“星星和留言会公开显示在共享星空，仅表达线上支持意向，不代表捐款或物资已经送达”，并提醒不要填写任何人的真实姓名、联系方式、住址或儿童可识别信息；访客需确认后才能发布。
- 捐款金额、支付方式、模拟订单、支付凭证、旧项目名称全部移除。当前网站“不收款”的说明及现有联系方式保留。

## 实现方案

在当前“参与支持”章节加入“点亮一颗线上微光”入口，打开与页面风格相协调的星空互动层，并沿用旧系统的 `night-sky.jpg` 夜空底图。访客选一个预设支持方向、写一句不超过 60 字的留言，并确认留言公开后点亮。成功时，星星从按钮位置沿原有弧线路径飞入画布；点选共享星星可读到该星对应的支持方向、留言及时间。留言插入星星提示框时使用 `textContent`，不使用 `innerHTML`，不解释或运行 HTML。计数只统计实际读取到的共享支持星星，不把背景装饰星算作参与人数。

前端继续使用原生 HTML、CSS、JavaScript，不引入应用框架。将星空交互拆为独立脚本和样式，减少对现有页面脚本及“联系支持”交互的影响。弹层提供明确的关闭按钮、Esc 关闭、焦点管理、键盘可达控件和移动端布局；遵从系统减少动态效果设置，关闭动效时仍能完成点亮和查看。

## 共享数据与隐私

当前站点没有星空后端；旧版草稿的 `donation_stars` 表会保存捐款金额、旧项目名和昵称，因此不用于本功能。使用旧共享星空草稿对应的 Supabase 项目配置，但创建语义独立的 `public.support_stars` 表；不在站点中放入服务端密钥。

每行仅包含：

| 字段 | 用途 |
| --- | --- |
| `id` | 数据库生成的行标识 |
| `client_id` | 浏览器随机生成的去重标识 |
| `support_type` | 三个预设支持方向之一 |
| `message` | 1–60 字公开纯文本留言 |
| `x`, `y` | 星星画布位置，并由数据库限制范围 |
| `created_at` | 数据库生成的公开点亮时间 |

启用 RLS；匿名访客仅可读取和新增符合字段约束的星星，不可修改或删除。前端读取最新 80 颗共享星星并订阅新增记录。留言长度由数据库再次校验；访客提交的文字不经过 HTML 渲染。留言即刻公开，站点管理者需能从 Supabase 项目后台发现并删除不当记录；匿名访客不能删除或修改留言。若共享服务未配置或请求失败，当前访客仍可在本机看到自己刚点亮的星，但页面必须明确提示“仅本机可见，未同步到共享星空”，且不得计入共享数量。

因为这是静态公开网站，匿名新增接口仍可能受到自动化刷入；60 字长度限制、支持方向白名单与数据库约束不能提供强力限流，也不能自动判定留言内容是否合适。发布提示、前端冷却和后台删除只能降低或处理滥用，不能替代服务端反垃圾。如果需要可靠抗刷或预审留言，后续应增加带速率限制、人机验证或审核队列的服务端接口。

## 文件与接口范围

- `index.html`：添加入口、可访问的互动层、公开留言确认、共享状态提示和脚本引用。
- `assets/night-sky.jpg`：从原系统素材复制，用作互动层夜空底图。
- `support-stars.css`：只负责新增星空层的布局、画布、表单、留言长度提示与移动适配。
- `support-stars.js`：负责选择、动画、画布、提示、Supabase 读写/订阅及本机失败状态。
- `supabase/support_stars.sql`：创建专用表、约束、RLS 策略和 Realtime 发布设置。
- `tests/test_support_stars.py`：验证页面不含真实或模拟支付入口，留言公开提醒、确认、长度限制与纯文本插入路径存在，SQL 字段和策略符合设计，失败文案区分共享与本机状态，当前站点其他章节继续保留。

## 失败处理与上线条件

- 共享星空初始化失败：显示本机星空状态，不阻塞原网站、课程表或联系入口。
- 新星写入失败：保留本机动画与本机状态，同时清楚说明其他访客看不到这颗星；不显示“全站已点亮”或共享成功提示。
- 网络恢复后重新载入最新共享快照；不把未成功同步的本机星星悄悄覆盖到共享表。
- GitHub Pages 可以部署静态代码，但 Supabase 表需要先应用一次 SQL。没有应用迁移前，共享读取/写入不可用，页面只能提示本机状态。
- 正式收款主体和渠道仍未确定；本互动与任何支付流程完全分离。

## 验收

1. 访客可以选择三个支持方向之一，确认公开提示后点亮星星。
2. 星星飞入与点击查看玩法仍在；另一访客新增的共享星星可见。
3. 访客需确认留言公开；留言最多 60 字，其他访客可在点选星星时查看留言。
4. 留言以纯文本显示；页面和网络写入中没有金额、支付方式、捐款订单、收据或服务端密钥。
5. 离线或 Supabase 错误时提示明确，且本机星星不会伪装成共享记录。
6. 手机布局无横向溢出；键盘可关闭弹层并操作支持方向及留言；减少动态效果时互动仍完整。
7. 现有学校信息、行程、课表、支持联系入口和捐款渠道“不收款”说明继续正常工作。
